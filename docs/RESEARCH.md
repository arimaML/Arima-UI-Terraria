# Resource Packs для Terraria — исследование под UI-пак

Дата: 2026-02. Цель проекта: `projects/Terraria-UI` — пак, который меняет **интерфейс** (HUD, инвентарь, меню).
Документ фиксирует механику ванильных Resource Packs (Desktop **1.4.5.x**) и то, что из этого следует для UI.

Источники: [вики Terraria — Resource Pack](https://terraria.wiki.gg/wiki/Resource_Pack),
[официальный гайд Leinfors (Re-Logic) по Workshop](https://forums.terraria.org/index.php?threads/the-ultimate-guide-to-content-creation-and-use-for-the-terraria-workshop.100652/).

---

## 1. Что это такое и где границы

Resource Pack — это **замена** уже существующих ассетов игры (спрайты, музыка, звуки, локализация).
Пак не добавляет новый контент и не меняет логику: код остаётся ванильным, поэтому новые кнопки, панели,
анимации интерфейса паком сделать **нельзя** — можно только перерисовать те картинки, которые игра уже рисует.

Ключевое следствие для UI: если хочется «другой интерфейс» — это возможно ровно в тех местах, где ваниль
рисует текстуру. Всё, что рисуется кодом (полоски из примитивов, текст, позиции элементов), паком не трогается.

Пак — чисто косметика: достижения не затрагивает, на серверах/в мультиплеере работает у каждого локально.

## 2. Структура пака

Пак — это **папка** или **zip** (7z/rar не поддерживаются). Внутри — строго на корне:

```
PackName/            (или корень .zip)
├── pack.json        ← ОБЯЗАТЕЛЕН, иначе пак не виден игре
├── icon.png         ← опционально; любой размер, игра ужимает до 60×60
└── Content/
    ├── Images/      ← основной раздел: .png, пути 1:1 как в игре
    ├── Music/       ← .wav / .mp3 / .ogg
    ├── Sounds/      ← только .xnb (скомпилированные!)
    └── Localization/ ← .json / .csv, имя начинается с кода языка (en-US, ru-RU, …)
```

`pack.json`:

```json
{
  "Name": "Pack Name",
  "Author": "Author",
  "Description": "Текст. Перенос строки — через \\n",
  "Version": { "major": 1, "minor": 0 }
}
```

Грабли: `Version` — **объект с целыми числами**, не строка `"1.0"`. Ключи PascalCase. `pack.json`
должен лежать ровно в корне (частая ошибка — двойная вложенность `MyPack/MyPack/pack.json`).
`pack.json` влияет только на отображение в игре, к странице Workshop отношения не имеет.

## 3. Правила для Content/Images (главное)

Валидный спрайт — одновременно **четыре** условия:

| Условие | Деталь |
|---|---|
| Формат | `.png` (в игре оригиналы — `.xnb`) |
| Имя | точно как у оригинала, меняется только расширение: `Heart.xnb` → `Heart.png` |
| Путь | та же подпапка внутри `Content/Images/`, что и у оригинала (`UI/...`) |
| Размер | **точно тот же канвас в пикселях** |

Terraria **никогда не масштабирует** спрайты. Неверный размер → спрайт рвётся/съезжает или пак молча
не применяется. Анимированные спрайты — это один лист со всеми кадрами: сохранять и общий размер,
и сетку кадров, иначе анимация «рассыпается».

Регистр имён важен: `heart.png` вместо `Heart.png` — тишина, без ошибки. Файлы ищутся по имени
регистрозависимо внутри `Content/Images/`.

## 4. Специфика UI

- Почти весь интерфейс лежит в **`Content/Images/UI/`** (у этой папки есть свои подпапки — их надо
  повторять в паке). Часть элементов — в корне `Images/`: например логотип `Logo.png`, фоны слотов
  инвентаря (`Inventory_Back*.png`), курсоры, `Cursor_*.png`.
- Референс для практики из официального гайда: `Content/Images/UI/Achievement_Borders.png` — он же
  рамка иконки пака в меню Resource Packs, поэтому изменение видно сразу.
- UI-элементы рисуются по **фиксированным прямоугольникам** из кода. Если холст больше/меньше —
  получим обрезку, растяжение или «поехавшие» рамки, а не аккуратный ресайз.
- Внутри игры спрайты выводятся с **увеличением ×2** относительно файла (`Heart.png` 32×32 выглядит
  как 64×64). Поэтому рисовать надо в «половинном» масштабе и помнить: 1 пиксель файла = 2 пикселя на экране.
- Масштаб интерфейса (`Settings → UI Scale`, у tModLoader выше 200% через `config.json`) кратен, поэтому
  пиксель-перфект достигается при 100%; на нецелых масштабах неизбежна интерполяция — рисовать
  «толстые» формы и контрастные края, а не hairline-линии в 1 px.
- Панели/рамки в Terraria часто **растягиваются или нарезаются по 9-slice** (углы + тайлящиеся края).
  Рисуя такую текстуру, нельзя запекать в неё градиент по всей длине — он поедет при растяжении.
  Безопасно: симметричные углы, однородные края, мягкая середина.
- Полупрозрачность и цвет: PNG с альфой поддерживается; но помни, что поверх UI идёт `Main.UIScale`
  и цветовые множители из кода (например, подсветка слота при наведении) — чистая белая база
  перекрашивается предсказуемо, а насыщенный цвет базы умножается и уходит в грязь.
- Шрифты: штатно Resource Pack **не заменяет** шрифты (в вики раздел Images/Music/Sounds/Localization
  только). В сообществе есть «font packs» — они подменяют `Content/Fonts/*.xnb` (атлас глифов,
  сгенерированный внешним генератором шрифтов). Это хак, требует совпадения метрик и очень хрупок —
  в проекте считаем **вне основного скоупа**, только если очень понадобится.

## 5. Ограничения, о которых стоит знать заранее

| Хочу | Возможно паком? |
|---|---|
| Перерисовать сердца/ману/слоты/рамки/кнопки/курсор | Да |
| Поменять размер или положение элементов UI | Нет (это код) |
| Добавить новые элементы/иконки | Нет |
| Заменить текст/названия предметов | Да, через `Content/Localization` |
| Заменить музыку | Да, `.wav/.mp3/.ogg` в `Content/Music` (`Music_1..104`) |
| Заменить звуки | Да, но только **`.xnb`** — нужен конвертер |
| Заменить шрифт | Только хаком с `Fonts`, вне скоупа |
| Заменить UI модов (Calamity и т.п.) | Нет, другой namespace |

## 6. Установка, порядок, отладка

- Папка: `%USERPROFILE%\Documents\My Games\Terraria\ResourcePacks` (для tModLoader — своя ветка
  `...\Terraria\tModLoader\ResourcePacks`, если используешь L1.4-совместимый путь; Workshop-паки
  из Terraria в tModLoader подхватываются).
- Включение: главное меню → Workshop Hub / Resource Packs → перенести пак вправо.
- Конфликт: если два пака меняют один файл — побеждает **верхний** в списке Enabled Packs.
- С версии **1.4.5.0** паки-папки **hot-reload**: изменил PNG — игра перечитала без перезапуска.
  Это сильно ускоряет итерации: держим пак папкой в `ResourcePacks`, а zip собираем только на релиз.
- `.zip`-паки: 1.4.5.3 починил их загрузку. Zip нельзя публиковать в Workshop (только папкой).
- Диагностика: если не применилось — проверять по порядку: включён ли пак → не двойная ли вложенность →
  точное имя (регистр) → размер канваса → порядок в списке.

## 7. Пайплайн, который предлагаю для этого проекта

1. **Инвентаризация.** Из `Steam/steamapps/common/Terraria/Content/Images/**` собрать манифест:
   путь → (ширина, высота, формат). Размеры читаются прямо из заголовка `.xnb`, без распаковки
   (`tools/xnb_manifest.py`). Это единственный надёжный источник истины по именам и размерам.
2. **Референс.** Оригиналы для «до/после» достаются `TConvert` (форум Terraria, извлекает xnb → png).
   Оригиналы в пак не кладём и не перепубликуем — только свои перерисовки.
3. **Рисование.** Работаем в точных размерах канваса из манифеста. Для каждого элемента — отдельный
   `.png` в `pack/Content/Images/...`. Прозрачные поля не обрезать: канвас = оригинал.
4. **Валидация.** `tools/build_pack.py` сверяет каждый PNG с манифестом (имя, путь, размер),
   проверяет `pack.json` и собирает `dist/<name>.zip` с `pack.json` в корне.
5. **Тест в игре.** Папка → `ResourcePacks`, hot-reload, скриншоты до/после.
6. **Релиз.** zip для ручной установки + при желании публикация в Workshop (только папкой).

## 8. Альтернатива: tModLoader-мод

**Решение по проекту: идём модовым путём** (см. [MOD-ROUTE.md](MOD-ROUTE.md)). Итог сравнения:

| | Resource Pack | tModLoader мод |
|---|---|---|
| Где работает | ваниль + tModLoader | только tModLoader |
| Что можно | замена существующих спрайтов (+музыка/звуки/текст) | любой UI, произвольные размеры, новые элементы |
| Порог | PNG + `pack.json` | C#, сборка `.tmod` |
| Совместимость с другими паками | да, слоями | частично |

Пак остаётся в проекте как вспомогательный слой: перерисовку без изменения габаритов дешевле
делать паком (в tModLoader он тоже работает), а мод подключать только там, где нужна структура.
В `projects/Mod-terr` уже есть рабочий tModLoader-проект (HeartSlots) — инфраструктуру сборки
переиспользуем.

## 9. Частые причины «пак не работает»

1. Не включён в правой колонке (лежит в Available — ничего не делает).
2. Двойная вложенность: `MyPack/MyPack/pack.json`.
3. Ошибка в имени/регистре (`item_1.png` вместо `Item_1.png`).
4. Неверный размер канваса.
5. Потеряна подпапка (`UI/`), файл положен в корень `Images`.
6. `Version` строкой → невалидный `pack.json`.
7. Пак ниже в списке приоритетов, чем конкурент.
8. Правки в другом файле, чем думаешь (у UI-элементов бывают `_Border`, `_Back`, `_Fancy` варианты).
