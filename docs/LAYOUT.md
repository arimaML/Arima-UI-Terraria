# Раскладка UI: как мы попадаем в координаты

## Проблема

Ванильный инвентарь считает свои прямоугольники внутри `Main.DrawInventory` из
`Main.screenWidth/Height`, `Main.UIScale` и количества слотов. Наружу эти числа не выведены.
Хуже: с другими модами (лишние колонки аксессуаров, дополнительные слоты) раскладка сдвигается —
на скриншоте игрока инвентарь занимает нестандартную область, а экипировка вынесена к правому краю.

Поэтому жёсткие константы «как в ванили» не годятся: панель должна либо следовать за реальной
раскладкой, либо калиброваться.

## Что уже сделано

| Механизм | Где | Статус |
|---|---|---|
| Панель **под** инвентарём (до отрисовки ванильных слотов) | `Systems/InventoryPanel.cs`, хук `On_Main.DrawInventory` | скомпилировано, хук подтверждён |
| Прямоугольник панели из конфига | `UiConfig.PanelX/Y/W/H` | есть, значения ждут калибровки |
| Линейка в UI-единицах + вывод разрешения и UI-scale | `Systems/GlassDemo.cs`, `DebugInfo` | есть |
| Зонд API (`On_ItemSlot`, поля `Main`) | `Systems/ApiProbe.cs` | пишет строки на экран |

## Как калибровать (один скриншот)

1. Включить `DebugInfo`, открыть инвентарь.
2. Сделать скриншот: в левом верхнем углу будет строка вида
   `2560x1440  ui 1.50  inv 1`, ниже — вывод зонда, по краям — линейка с шагом 50 и подписями каждые 200.
3. По линейке читаются координаты первого слота и внешние границы сетки → эти числа
   переносятся в `PanelX/Y/W/H`. Дальше панель стоит точно под содержимым.

## Следующий шаг (после калибровки)

Зонд покажет, есть ли в сборке `On_ItemSlot` и с какой сигнатурой. Если есть — панель можно будет
не калибровать руками, а выводить из фактических позиций слотов: мод запоминает прямоугольники,
которые ваниль рисует, и строит панель по их объединению. Тогда раскладка будет корректной
при любом наборе модов и любом разрешении.
