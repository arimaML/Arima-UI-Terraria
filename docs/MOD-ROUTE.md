# Модовый путь (tModLoader) — карта решений

Платформа выбрана: **tModLoader-мод**, не только resource pack. Здесь — что это меняет по сравнению
с паком, какие есть механизмы, где риски и что нужно проверить на локальной сборке.

Базовые правила паков (имена, размеры, `pack.json`) остаются полезными: мод всё равно работает
с теми же ванильными спрайтами и теми же координатами. См. [RESEARCH.md](RESEARCH.md).

---

## 1. Что даёт мод, чего не даёт пак

| Возможность | Пак | Мод |
|---|---|---|
| Перерисовать существующий спрайт | да | да |
| Другой размер/пропорции спрайта | **нет** (игра не масштабирует) | да, если перехватить и отрисовку |
| Другая раскладка/позиции элементов | нет | да |
| Новые элементы (панели, бары, кнопки) | нет | да |
| Анимация, состояния, настройки, переключение тем | нет | да |
| Работает в ванильной игре | да | **нет** |
| Совместимость с другими паками | да, слоями | частично (кто последний — тот и прав) |

Ресурспак в tModLoader тоже работает (для ванильных спрайтов), но **не меняет текстуры модов**
(подтверждено обсуждением Calamity: контент модов паками не переопределяется).
Отсюда рабочая гибридная схема: пак — для «просто перерисовать», мод — для структурных изменений.

## 2. Механизм A: подмена полей `TextureAssets`

Класс `Terraria.GameContent.TextureAssets` — публичные статические поля вида `Asset<Texture2D>`
([док tModLoader](https://docs.tmodloader.net/docs/stable/class_texture_assets.html)).
Проверено по документации: существуют `Heart`, `Heart2`, `Mana`, `InventoryBack` + `InventoryBack2..19`,
`Cursors` (массив), `CursorRadial`, `Logo`, `Map`, `Buff[]`, `Item[]` и т.д.

Идея: в `PostSetupContent()` подменить нужные поля на свои текстуры:

```csharp
TextureAssets.Heart = ModContent.Request<Texture2D>("TerrariaUI/Assets/UI/Heart");
TextureAssets.Mana  = ModContent.Request<Texture2D>("TerrariaUI/Assets/UI/Mana");
```

Плюсы: минимум кода, работает там, где ваниль каждый кадр читает поле.
Минусы и риски:
- Работает **только** если код действительно берёт текстуру из поля в момент отрисовки. Там, где
  ваниль кэширует ссылку в локальной переменной или тянет `Main.Assets.Request("Images/...")` напрямую,
  замена поля не подействует — нужен detour (механизм B). **Проверить по каждому элементу.**
- Ванильная отрисовка часто берёт `texture.Width/Height` и режет по этим размерам. Если поставить
  текстуру другого размера, получим обрезку/сдвиг, а не увеличение. Т.е. этот механизм даёт свободу
  в **арте**, но не в **габаритах** — для габаритов нужен B.
- Конфликт: два мода, меняющие одно поле, — побеждает загрузившийся позже.

## 3. Механизм B: перехват отрисовки (detours)

Точки входа tModLoader:
- `ModSystem` + `On_Main.DrawInterface` / `DrawInventory` / `DrawPlayerLife` и другие `On_`-хуки
  (`Terraria.On_*` namespace, генерируется tModLoader'ом).
- `IL.*` правки, если нужно заменить середину метода.
- Свои элементы: `UIElement`, `UIMessageBox`, `UIScrollbar` и т.п.

Что даёт: полный контроль над прямоугольником, масштабом, порядком слоёв. Что стоит: переписывать
логику позиционирования вручную и следить за `Main.UIScale`, `Main.screenWidth/Height`, режимами
инвентаря. Дороже в поддержке, ломается при обновлениях игры.

Правило: сначала A, если элемент «не слушается» — точечно B для него, а не всё подряд.

## 4. Специфика UI, которая остаётся даже в моде

- Координаты ванильного UI жёстко зашиты; «сдвинуть» элемент = перехватить его отрисовку.
- Спрайты в мире/инвентаре рисуются с ×2 (`SpriteBatch` с масштабом 2 для `Main.UIScale = 1`),
  у UI-панелей масштаб свой. Рисуя вручную, надо повторять эти множители, иначе элементы «поплывут»
  относительно ванильных.
- Пиксель-перфект при нестандартном UI Scale недостижим — рисовать толстые контуры, не hairline.
- 9-slice/растягиваемые панели: рисовать через `Utils.DrawSplicedPanel`/`DrawImage` с правильными
  краями, а не одной растянутой картинкой.

## 5. Предлагаемая архитектура мода

```
TerrariaUI/
├── build.txt
├── description.txt
├── icon.png
├── TerrariaUI.cs                 // Mod
├── TerrariaUI.csproj             // <Import ... tMLMod.targets>
├── Assets/UI/…                   // свои PNG (любые размеры)
├── Systems/
│   ├── UiTextureReplacer.cs      // ModSystem: подмена TextureAssets.*
│   └── UiDrawHooks.cs            // ModSystem: On_* detours для структурных правок
├── Configs/UiConfig.cs           // ModConfig: группы (HUD/инвентарь/меню/курсор), масштаб, тема
└── Localization/…                // en-US.hjson, ru-RU.hjson
```

Сборка — как в `projects/Mod-terr/HeartSlots`: `<Import Project="…/tModLoader/tMLMod.targets" />`,
локальный tModLoader обнаружен по пути `D:\Program Files (x86)\Steam\steamapps\common\tModLoader`.

## 6. Что нужно проверить спайком (до большой работы)

Мелкий тестовый мод «Heart ×2» (15 минут):
1. Присваиваются ли `TextureAssets.Heart` / `.Mana` из мода (компилируется ли, не `readonly` ли поле).
2. Читает ли ваниль эти поля каждый кадр (визуально: сердце меняется сразу).
3. Что происходит при текстуре другого размера: кроп, растяжение или сдвиг — от этого зависит,
   нужен ли detour для каждого элемента.
4. Не ломается ли `Main.DrawPlayerLife` при нестандартном соотношении сторон.

Ответы на 1–4 фиксируем в этом файле и только потом рисуем серьёзный арт.

## 7. Чего по-прежнему не хватает

- **Бриф**: что именно перерисовываем в v1 (сейчас заявлены все четыре группы: HUD, инвентарь,
  меню, курсор — это большой объём, лучше резать на этапы).
- **Список имён и размеров** ванильных UI-спрайтов: берётся из `tModLoader/Content/Images` (или
  `Terraria/Content/Images`) через `tools/xnb_manifest.py`. Нужно разрешение на чтение папки игры.
- **Стиль**: референсы, палитра, «пиксель-арт как в ванили» vs «чистый современный UI».
